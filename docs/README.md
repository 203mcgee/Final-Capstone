# Portfolio Skills API

A full-stack skills management system built for my portfolio. Visitors can browse and search my skills, logged-in visitors can endorse a skill once, and administrative actions (creating, updating, or deleting skills) are strictly restricted to the admin role. All data lives in MongoDB Atlas to survive redeployments.

## 🛠️ Tech Stack

* **Frontend:** React, Vite, React Router, Tailwind CSS *(Hosted on Vercel)*
* **Backend:** Node.js, Express *(Hosted on Render)*
* **Database:** MongoDB Atlas with Mongoose
* **Auth & Security:** bcrypt, JSON Web Tokens (JWT), Zod, Helmet, express-rate-limit, CORS

---

## ✨ Features

* **Custom Atomic IDs:** Skills stored in MongoDB with custom IDs (`SKL-0001`) generated by an atomic counter document.
* **Server-Side Search & Sort:** Search and sorting processed on the server, directly within the database query.
* **JWT Authentication:** Register and login with hashed passwords and one-hour JWTs.
* **Atomic Endorsements:** One endorsement per user per skill, executed using a single atomic update.
* **Admin Authorization:** Admin-only create, edit, and delete, enforced by role-based middleware.
* **UX & UI Standards:** Loading, error, and empty states on every data request, alongside labeled inputs.

### 📡 API Routes

| Method | Route Path | Access Level | Rate Limit | Purpose / Behavior |
| :---: | :--- | :---: | :---: | :--- |
| `GET` | `/api/health` | Anyone | None | Health check returning `{ "status": "ok" }` |
| `POST` | `/api/auth/register` | Anyone | Standard | Registers a visitor account (returns token + user payload; `409` if email exists) |
| `POST` | `/api/auth/login` | Anyone | **5 req / 15m** | Authenticates credentials and issues JWT (`401` invalid credentials, `429` rate limited) |
| `GET` | `/api/auth/me` | Logged In | Standard | Returns authenticated user's `id`, `email`, and `role` |
| `GET` | `/api/skills` | Anyone | None | Lists skills with optional parameters (`?search=`, `?category=`, `?level=`, `?sort=`) |
| `GET` | `/api/skills/:id` | Anyone | None | Returns details for a single skill (`404` if not found) |
| `POST` | `/api/skills/:id/endorse` | Logged In | Standard | Adds user's endorsement atomically (`409` if already endorsed) |
| `POST` | `/api/skills` | **Admin Only** | Standard | Creates a new skill with next custom ID counter (`400` validation error, `409` duplicate name) |
| `PATCH` | `/api/skills/:id` | **Admin Only** | Standard | Updates skill fields (`name`, `category`, `level`, `yearsExperience`) |
| `DELETE` | `/api/skills/:id` | **Admin Only** | Standard | Removes a skill record from database |


## Honest Counter Test

## Security
Every request body is validated with Zod, stripping any unknown fields. The server uses Helmet, sanitizeFilter, login rate limiting, and CORS restrictions limited to the front-end URL. Passwords are hashed with bcrypt, and the admin account can only be created by the seed script. The full security audit with evidence can be found in docs/security-audit.md.

## Known Limitations
Render's free tier sleeps when idle, so the first request is slow.
Custom IDs can skip a number when a create request fails after the counter has incremented. Gaps are expected with this approach.
The login token is stored in localStorage and lasts one hour with no refresh token.
There is no password reset, and visitors cannot change or delete their accounts.
The login rate limit is enforced per IP address.
Atlas free clusters pause after 30 days without activity.
